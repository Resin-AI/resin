# Resin V1.0.3 Release Notes

**Release Tag**: `v1.0.3`  
**Release Date**: `Pending Release Candidate Publication`  
**Status**: Release Candidate (Prepublication Release Gate)  
**Parent Roadmap Epic**: `#22` (`Complete V1 Qualification & Prepublication Release Gate`)

Resin V1.0.3 is a prepublication release candidate that compiles recurring coding-agent work into tools designed to use less inference, lower inference cost, and complete matching work faster. It completes GitHub epic `#22` with end-to-end support for automated session observation, opportunity clustering, pure-compute and brokered tool synthesis, sandboxed preactivation verification, real canary traffic routing, and multi-harness support for Claude Code, Codex CLI, and Oh My Pi (OMP).

---

## Highlights & Architectural Milestones (REM-001 through REM-020)

### 🛡️ Fail-Closed Security & Sandbox Isolation

- **Fail-Closed Safety Gate ([REM-001](release-evidence.md#authoritative-traceability-matrix))**: Real-time evaluation of tool security invariants before execution with automatic fail-closed blocking when invariants are unmet.
- **Broker-Only Filesystem Access ([REM-003](release-evidence.md#authoritative-traceability-matrix))**: Strict kernel-level and process-level isolation preventing direct disk access from evolved tools; all workspace mutations are broker-mediated with symlink escape defense.
- **Non-Disclosing Secret References ([REM-004](release-evidence.md#authoritative-traceability-matrix))**: High-security token proxying where generated tools reference secrets symbolically via `$secret:NAME` handles without runtime environment disclosure.
- **Command & Path Validation ([REM-006](release-evidence.md#authoritative-traceability-matrix))**: Strict deterministic allowlist runner restricting subprocess invocations to approved binaries and verified relative paths.

### 🔒 Privacy-Preserving Session Observation

- **Pre-Persistence Session Redaction ([REM-005](release-evidence.md#authoritative-traceability-matrix))**: Automated multi-stage redactor stripping API keys, tokens, SSH keys, emails, and IP addresses before session records touch local disk or transit boundaries.
- **Opportunistic Pattern Clustering ([REM-011](release-evidence.md#authoritative-traceability-matrix))**: Zero-plaintext pattern mining identifying high-frequency developer workflows and synthesizing optimized tool proposals without uploading raw telemetry.

### 🧬 Autonomous Tool Evolution & Synthesis

- **AST-Guided Mutation Engine ([REM-008](release-evidence.md#authoritative-traceability-matrix))**: Deterministic grammar-constrained TypeScript AST synthesizer generating type-safe, minimal tool implementations.
- **Pure-Compute Synthesis ([REM-009](release-evidence.md#authoritative-traceability-matrix))**: Hermetic synthesizer producing pure data-transformation and arithmetic tools with no ambient dependencies.
- **Brokered Tool Synthesis with Bounded Repair ([REM-010](release-evidence.md#authoritative-traceability-matrix))**: Capability-minimized synthesis incorporating iterative static-analysis feedback loops bounded to at most 3 repair iterations.
- **Sandboxed Preactivation Verification ([REM-007](release-evidence.md#authoritative-traceability-matrix))**: Multi-gate verification suite executing tool static probes, bytecode compilation, execution timing limits (500ms ceiling), and memory ceilings (64MB) prior to active promotion.
- **Evolution Loop Orchestrator ([REM-012](release-evidence.md#authoritative-traceability-matrix))**: Distributed worker coordinator with state-machine leases, exponential backoff retries, and dead-letter quarantine.

### 🌐 Multi-Harness Integration & Traffic Governance

- **Local MCP Gateway Proxy ([REM-013](release-evidence.md#authoritative-traceability-matrix))**: Zero-latency local proxy routing tool calls across multiple AI agent harnesses with protocol translations.
- **Canary Routing & Automatic Quarantine ([REM-014](release-evidence.md#authoritative-traceability-matrix))**: Local MCP Gateway dynamically shifts traffic to canary versions and triggers instant automatic quarantine upon abnormal error rates.
- **Multi-Process E2E Topology ([REM-015](release-evidence.md#authoritative-traceability-matrix))**: Validated complete topology running as genuine OS subprocesses with real IPC/MCP transports and SQLite storage.

### 📦 Distribution, Qualification & Governance

- **Zero-Dependency NPM Bootstrap ([REM-016](release-evidence.md#authoritative-traceability-matrix))**: Single-command installation (`npx resin init`) with signed tarball downloads and platform user service registration.
- **Multi-Harness Qualification ([REM-017](release-evidence.md#authoritative-traceability-matrix))**: Comprehensive qualification suites covering Claude Code, Codex CLI, and Oh My Pi.
- **5-Lane Platform Qualification Matrix ([REM-018](release-evidence.md#authoritative-traceability-matrix))**: Automated qualification across Linux x64/arm64, macOS Intel/Apple Silicon, and WSL.
- **Cloud Staging Qualification ([REM-019](release-evidence.md#authoritative-traceability-matrix))**: Verified encrypted backup/restore rehearsals, node crash fault injection, and 24-hour equivalent continuous soak loops.
- **PR-Only Release Gates & Governance ([REM-002](release-evidence.md#authoritative-traceability-matrix))**: Automated release gating preventing direct-to-main merges and enforcing cryptographic supply chain provenance.
- **One-Command Fresh-User Onboarding**: `npx resin init` verifies the signed release, presents the capability/privacy plan with an explicit approval prompt (bypassed with `--auto-approve`), pairs via RFC 8628 (browser auto-open plus printed complete URL and user code, or structured JSON verification event in `--json` mode), writes owner-only `~/.resin/state/device-token.json` plus optional ancillary vault (distinct from the local IPC token), registers harnesses at `--gateway-url` (default `http://127.0.0.1:9400/mcp/sse` only when omitted), and installs/starts/health-checks the non-root user service under `~/.resin/` (`~/.resin/config`, `~/.resin/logs`). `--local-only` and `--non-interactive` (requiring one authorization option like `--auto-approve` or `--capabilities-file`, and one pairing option like pre-provisioned credentials or `--local-only`) are explicit. `resin login` reuses valid cached same-origin credentials unless `--force`. Failed service setup best-effort remotely revokes a newly paired device before local rollback. `resin logout` revokes then purges local cloud credentials while local MCP continues.

## Lifecycle, Recovery, And Rollback

Security and lifecycle boundaries that ship with this CLI:

- **Credentials**: Canonical owner-only `~/.resin/state/device-token.json` (mode `0600`) plus optional ancillary vault when SecretManager is configured. Distinct from daemon IPC `auth.token`. Tokens are not written to harness config, `.resin/project.json`, `.resin/resin.lock`, logs, or doctor/status JSON.
- **Identity**: Console device approval shows the selected account and workspace; one approval cannot bind another tenant.
- **Privacy**: Device approval cannot silently enable raw transcript/source upload. Cloud sync stays off unless the install privacy plan grants it.
- **Service**: Default install registers a non-root user unit under `~/.resin/`, starts it, and fails closed on unhealthy setup (remotely revoking a newly paired device before rolling back pairing and earlier mutations).
- **Offline**: Locked local meta-tools (`search_tools`, `get_tool_schema`, `invoke_tool`, `manage_tools`) remain on the gateway after logout or cloud outage.
- **Status**: `resin status` reports `RUNNING` / `STOPPED` / `NOT INSTALLED`, IPC `CONNECTED` / `DISCONNECTED`, cloud `AUTHENTICATED` / `LOCAL ONLY (Cloud Unconfigured)` (derived from the completed install journal) / `NOT AUTHENTICATED` (plus expiry and reasons), and safety-gate `PASS` / `BLOCKED` / `OVERRIDE`. Note that status evaluates local credentials and does not proactively query server revocation.
- **Doctor / repair**: `resin doctor` diagnoses; `resin repair` or `resin doctor --fix` recreates directories, clears a stale lockfile, installs/starts the user service, reattaches harness MCP, and rewrites the local safety attestation. There is no `--export-bundle`, `--rollback-tool`, or `--disable-all-evolved-tools` flag.

### Install rollback

```bash
npx resin init --rollback-install
```

### Signed binary upgrade / rollback

```bash
# Upgrade only to the version authenticated by the signed production channel
resin upgrade
resin upgrade --target-version <version> --force
# Health-gate failure rolls back unless --no-rollback
```

### Tool catalog rollback

Use the locked `manage_tools` MCP action (`rollback`) from a connected harness. There is no `resin repair --rollback-tool` CLI flag.

For recovery guidance, refer to [Client & Cloud Rollback Procedures](rollback-procedure.md) and the [Troubleshooting Guide](../user/troubleshooting.md).
